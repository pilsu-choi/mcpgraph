# v2 m9: coding-agent hook

**Done when** (AGENTS.md): recorded hook payloads produce the right allow/deny/ask output, and a manual
run in Claude Code blocks `psql -c "DROP TABLE users"`.

- Payloads: `testdata/hooks/{claude-code,codex}/` (see its README for which are captured and which
  are hand-written). `TestHookCommand` checks stdout byte for byte, exit code and the audit line.
- Manual run (Claude Code 2.1.302, project-local `.claude/settings.json` with the printed config,
  `onFailure: block`): the model reported
  `PreToolUse:Bash hook error: mcpgraph blocked this by rule block-destructive-sql: Destructive SQL is blocked: ...`
  and the audit log got one `deny` / `block-destructive-sql` / source `hook` line. The first attempt
  (`Run exactly this shell command: ...`) was refused by the model itself before any tool call, so
  the hook was not exercised; the second prompt framed it as a sandbox test.

## Delivered

- [`internal/hook`](../components/2026-10-18-hook.md) and `mcpgraph hook <claude-code|codex>
  [--policy] [--decision-timeout] [--print-config] [--bin]`.
- Allow prints nothing (no auto-approve). Deny and ask follow the agent formats; Codex has no ask, so
  ask is a deny that says human approval is needed.
- Fail closed: bad payload, bad policy, unknown agent, wrong event -> reason on stderr, exit 2. A slow
  or crashing engine -> deny with rule `mcpgraph-fail-closed` (policy.Judge).
- `loadEngine` is split: `buildEngine` returns the error (hook), `loadEngine` wraps it in a failing
  engine (proxy). `notYet` stub removed.
- `--print-config` prints the settings snippet and writes nothing (hard rule 1).
- `captured-bash-echo.json`: a real Claude Code payload. New fields seen: `prompt_id`, `effort`.

## Notes

- File tools (Read/Edit/Write) are judged on their path only. Judging the `content` too would deny
  every edit of a file that mentions `DROP TABLE`.
- Codex: the real run did not reach the hook. See [Codex hooks](../research/2026-10-18-codex-hooks.md).
- Hook payloads can be large; stdin is capped at 8 MiB (over the cap = truncated JSON = blocked).

## Go concepts

- **`json.Decoder` on `io.LimitReader`** reads one JSON value from a stream with a hard size cap;
  struct decoding ignores unknown fields.
- **One struct, two values** (`ClaudeCode`, `Codex`) instead of an interface: the agents differ only
  in data (`NativeAsk`, `Matcher`), so no abstraction is needed.
- **Exit codes through errors**: `exitError{code: 2}` is returned from `RunE` and mapped in `main`;
  stderr text is written first with `cmd.ErrOrStderr()`.
- **Testing a cobra command in process** with `SetIn/SetOut/SetErr/SetArgs`, plus a stub `Engine`
  (interface satisfaction) that blocks on `ctx.Done()` to test the timeout.
- **Splitting a function by who handles the error**: `buildEngine` returns it, `loadEngine` turns it
  into a failing engine.
